# dev-notes

> 실제 경험과 근거, 반복적인 개선을 통해 쌓아가는 내 개발 원칙들

**Working principles, not final answers.**

완성된 정답이나 특정 기술 스택을 강요하는 매뉴얼이 아닙니다. AI와 소프트웨어를 개발하며 문제와 제약을 이해하고, 근거를 갖고 선택하고, 잘못된 판단을 안전하게 수정하는 방식을 기록하고 발전시키는 공간입니다.

## 현재의 원칙 (v0.1)

1. **문제 우선:** 기술보다 요구사항, 제약, 검증 가능한 동작을 먼저 정의합니다.
2. **판단의 비용 관리:** 지금 결정할 필요가 없거나 결과에 차이가 적은 선택은 오래 고민하지 않습니다.
3. **이해의 깊이 조절:** 시스템 구조, 상태 변화, 중요한 실패 경로는 이해하되 모든 구현을 줄 단위로 검토하지는 않습니다.
4. **근거와 검증:** AI의 제안은 가설입니다. 중요한 주장은 요구사항, 문서, 테스트, 작은 실험으로 확인합니다.
5. **되돌릴 수 있는 개발:** 작은 단위로 검증하고 Git으로 작업 상태를 보존합니다. 새 증거가 나오면 결정을 수정합니다.
6. **유연한 설계:** DDD, 클린 아키텍처, 프레임워크를 정답처럼 강제하지 않고 문제에 맞게 선택합니다.
7. **현실적인 자원 활용:** 시간, 사용량, 인지부채를 고려해 불필요한 에이전트 호출과 과도한 설계를 피합니다.

## AI와 협업하는 방식

AI에게 구현과 기술적 탐색을 위임할 수 있지만, 사람은 중요한 요구사항과 시스템 동작을 이해하고 설명할 수 있어야 합니다. 중요한 결정은 **왜 필요한지, 어떤 근거로 선택했는지, 무엇이 달라지면 결정을 바꿀지**를 간단하게 설명받습니다. 반면 사소하고 쉽게 되돌릴 수 있는 선택은 에이전트가 진행하도록 합니다.

코드와 에이전트 전용 규칙은 영어를 기본으로 하고, **사람이 읽고 판단해야 하는 설명과 기록은 쉬운 한국어**로 작성합니다.

## 사용 방식

각 프로젝트의 실제 요구사항과 기존 컨벤션이 우선입니다. 이 저장소의 지침은 다른 프로젝트에 자동 적용되지 않으므로, 필요할 때 해당 프로젝트에 복사하거나 알맞게 수정해 사용합니다.

스킬·훅·서브에이전트는 기본으로 강제하지 않습니다. 반복해서 나타나는 구체적인 문제가 있을 때만 추가하고, 도움이 되지 않는 규칙은 제거하거나 고칩니다.

**이 문서도 검증 중인 가설입니다.** 경험이 바뀌면 원칙도 바뀔 수 있습니다.
